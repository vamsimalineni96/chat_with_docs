# Eval reports

Generated by [`eval/run_eval.py`](../../eval/run_eval.py) (full orchestration lands in PR #7c). Each report scores the chat service on the hand-crafted Q&A set ([eval/qa_set.jsonl](../../eval/qa_set.jsonl)) along five axes:

- **Recall@5** — fraction of expected keywords that appear in the top-5 retrieved chunks
- **MRR** — Mean Reciprocal Rank, averaging the rank of the first relevant chunk
- **Groundedness** (1–5) — does the answer stick to the retrieved context, or does it hallucinate?
- **Accuracy** (1–5) — are the factual claims correct?
- **Completeness** (1–5) — does the answer cover the expected concepts?

This directory is the operational view of the Quality pillar (see [OBSERVABILITY.md §3.3](../OBSERVABILITY.md)).

## Why decomposed scoring

Pooja Palod's framework explicitly warns against single aggregate quality scores — they hide *where* the failure is. A row with `groundedness=5, accuracy=5, completeness=2` is a different failure (under-answering) than `groundedness=2, accuracy=4, completeness=5` (hallucinating). The reporter keeps them separate. The *Failures* section flags rows where **any** sub-score < 3 or recall@5 < 0.5 — a deliberately conservative bar that surfaces partial issues before they aggregate into a noticeable trend.

## How to read a report

Four questions a report answers in under a minute:

1. **How is the system doing overall?** → *Aggregate* row.
2. **Which book or category is weakest?** → *By book* / *By category* sections. Often `reasoning` and multi-hop `plot` questions trail `factual` recall.
3. **What specifically failed?** → *Failures* section. Each entry has the question, the answer, and the judge's reasoning — so you can see *why* it was flagged, not just *that* it was.
4. **Are scores drifting?** → compare across dated reports. A 10%+ drop in any axis over a week is Pooja's escalation threshold.

## On judge bias

Generator and judge are deliberately from different model families (Gemma vs Llama). Same-family judging tends to introduce self-preference bias — the judge rates answers in its own style higher even when an alternative is equally correct. Cross-family doesn't eliminate the issue (the judge can still over-trust the retrieved context, for example) but it removes the strongest source of false-positive scores.

If you suspect drift in the judge itself (the scores feel artificially high or low), spot-check ~10–20 random rows manually and compare your scores to the judge's. That's the "calibration against human labels" step Pooja describes; in a solo project it's done ad-hoc rather than as a continuous process.

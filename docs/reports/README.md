# Cost reports

Generated by [`scripts/cost_report.py`](../../scripts/cost_report.py). Each report attributes Langfuse-recorded token usage to a *task type* (`cache-hit` vs `rag-full`) and a *pipeline stage* (`embedding`, `rerank`, `llm`, …), priced against [`scripts/pricing.py`](../../scripts/pricing.py).

This directory is the operational view of the Cost pillar (see [OBSERVABILITY.md §3.2](../OBSERVABILITY.md)).

## Files

| File | Source | When it updates |
|---|---|---|
| [`cost_sample.md`](cost_sample.md) | `tests/fixtures/observations.json` | Whenever the fixture changes — checked in, regenerated by the workflow below |
| `cost_<YYYY-MM-DD>.md` | Live Langfuse | Generated locally by you; commit selectively |

## Regenerating

### From the checked-in fixture (no Langfuse needed)

```bash
python -m scripts.cost_report \
  --source file \
  --input tests/fixtures/observations.json \
  --output docs/reports/cost_sample.md
```

This is what CI does in the `Cost report (fixture)` workflow.

### From your live Langfuse

Requires `LANGFUSE_PUBLIC_KEY`, `LANGFUSE_SECRET_KEY`, and `LANGFUSE_HOST` set (the same env vars the app uses). With your local stack from `docker-compose up`:

```bash
python -m scripts.cost_report \
  --source live \
  --days 7 \
  --output docs/reports/cost_$(date +%Y-%m-%d).md
```

If the Langfuse SDK shape ever drifts, the only thing to patch is `fetch_from_langfuse()` in [`scripts/cost_report.py`](../../scripts/cost_report.py) — the aggregation logic is insulated from it.

> **Self-hosted vs Cloud.** The script deliberately uses only **v1 API endpoints** (`trace.list`, `trace.get`). The newer v2 `observations.get_many` is Cloud-only — calling it against self-hosted Langfuse returns 404 with `"v2 APIs are currently in beta and only available on Langfuse Cloud"`. The v1 approach (`trace.get` returning observations inline) works on both deployments at the cost of one extra HTTP round-trip per trace.

## How to read a report

The four useful questions a single report answers:

1. **What does an answer cost on average?** → "Cost per successful task" row in *Aggregate*.
2. **Is the cache earning its keep?** → Compare `$/task` for `cache-hit` vs `rag-full` in *By task type*. Cache hits should be 2–3 orders of magnitude cheaper, which means routing more traffic through the cache is the highest-leverage cost lever.
3. **Where would I save the most by optimizing?** → `Share` column in *By pipeline stage*. Whatever's at the top is where token / call-count reduction pays back the most.
4. **Are any models unpriced?** → If a span's model is missing from [`scripts/pricing.py`](../../scripts/pricing.py), it shows up with `$0.000000` but real token counts. Update the pricing table.
